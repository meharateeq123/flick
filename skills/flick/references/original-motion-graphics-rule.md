# Original Motion Graphics Only

When a scene requires a motion graphic, NEVER download, copy, extract, reuse, or directly place an already-animated motion graphic from YouTube, another video, another channel, a template preview, or any third-party video.

The system must CREATE THE MOTION GRAPHIC ITSELF, using the existing motion-graphics engine / Remotion / programmatic animation system to build an original graphic based on the narration.

| Narration mentions | Build |
|---|---|
| A statistic | Your own animated statistic/counter |
| A date | Your own timeline/date animation |
| A location | Your own map animation |
| A comparison | Your own comparison graphic |
| A process | Your own diagram/flow animation |
| A chart-worthy figure | Generate and animate the chart yourself |

**Do NOT:**
- Download an animated infographic
- Copy another creator's animation
- Use a YouTube motion-graphics clip
- Extract an animation from another video
- Reuse a third-party animated template without permission
- Simply place an existing animated scene into the timeline

The final motion graphic must be generated by our own system (Flick's Remotion build, Step 3) — never sourced.

## Design requirements

Every generated motion graphic must:
- Match the narration exactly
- Match the documentary's visual style
- Use the project's correct frame size
- Have clean typography and proper spacing
- Have no overlapping elements, no text-over-text collisions
- Keep all elements inside the safe area
- Use smooth, professional animation
- Be visually understandable within the available narration duration
- Transition naturally from the previous footage and into the next footage

## Motion graphic priority

Motion graphics are ONLY used when they genuinely improve understanding — never created simply because an animation looks good.

- If normal footage communicates the narration better → use footage.
- If a person's identity is important → use relevant video or an authentic image of that exact person.
- If data/date/map/comparison/process genuinely requires visual explanation → create an original motion graphic.

**The goal:** SCRIPT → relevant footage whenever possible → authentic image when necessary → original motion graphic only when necessary.
**Never:** SCRIPT → download existing animation → place it in the video.

## How this maps onto the pipeline

`auto-footage.mjs` already respects this by construction: it only ever downloads real video clips or still images — it has no code path that fetches an "animated graphic" from any source. When a data-driven line has no relevant footage/image, the scene is marked `RESERVED FOR MOTION GRAPHIC` and left undownloaded; building that reserved scene into an actual animation is Flick's Step 3 (Remotion), which must author it from scratch per the design requirements above, not source one from YouTube or any stock/template library.
